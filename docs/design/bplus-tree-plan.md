# B+ Tree Operations Lab: implementation plan

Status: B0–B4 software implemented locally, 2026-11-07. Version 0.4.0 adds
structured phone editing, preview and presenter/projector views to the B3
protocol. See the [B4 verification record](bplus-tree-b4-validation.md) for exact
artifacts and measured browser coverage. The B4 physical-phone criterion and
B5 load/release gates remain open.

## Scope and dependencies

Work in the plugin collection, using the active TeXStage code checkout as the
host. Keep original lecture-tools, lecture-tools-next, existing courses and
pins, archived Texstage and private media unchanged. Do not add a catalog
entry or installation instructions for a package that does not yet exist.

This is independent of the unfinished transaction lesson and relational visual
editor. It reuses the host contracts already exercised by those providers.
A classroom release includes lookup, range, insert and delete; an early engine
milestone must be labelled engine-only.

The baseline reviewed here is host
`de3351550f3553ca63023554521fbe84806ec94e` and collection
`5f00b62f6292de01e4eca067c8acd96dddf67eb9`, both local development history.
Recheck identity before implementation and record exact matching wheels.

## B0 — freeze schemas, examples and budgets

Engine specification and four bounded schemas are implemented. Full repair replay
now supplements the original snapshot checker. B3 now implements and measures
state/view storage; throughput and physical-device measurements remain later
work. The original design-only record is retained.

Translate the draft contract into machine-checked schemas and semantic validators.
Review source IDs, capacities, root exceptions, exact separator convention,
inclusive range stopping, no-op updates and automatic root handling.

Extend the independent design oracle into a bounded Python replay model.
It must verify repair preconditions and transient occupancy obligations; the
current snapshot checker explicitly does not do that. Author expectations
independently before using either implementation to generate a solution.

Exit criteria:

- Every worked fixture's full certificate, derived tree and claims agree.
  Two different legal split choices and two legal merge/donor choices pass.
- Wrong paths, wrong promoted keys, nonadjacent/cross-parent siblings, donor
  underflow, illegal occupancy, missing/extra repairs and bad final separator
  predictions produce the specified distinct outcomes.
- Concrete closed result/view schemas pass the current portable-profile checker;
  ordinary author-source schemas are not accidentally treated as portable.
- Enumerated maximum answer encoding fits the effect limit. Maximum valid
  facts/outcomes and worst actor keys/feedback/transition/view bytes fit the
  budgets. Finalise the exact work counter and admission ceiling.
- Record reviewed decisions and draft-contract version. Do not enlarge host
  limits to hide a model that does not fit.

## B1 — implement and package the pure engine

Implemented and checked locally as an engine-only portable wheel. The steps and
exit criteria below remain its maintenance/regression requirements. Hosted CI and
cross-platform artifact consumption are configured but not claimed as run locally.

Implement the independent JavaScript replay engine with fresh submission state
and start/load/evaluate/dispose. Generate a self-contained worker entry with the
collection's pinned bundler. First implement lookup and range on the fixed tree,
then insert (including cascading split), then delete (borrow, merge, separator
updates and contraction). No UI is needed to prove these rules.

Use the Python model and a separate sorted-set oracle. Enumerate all insertion
and deletion permutations over a small key universe, all legal repair choices
for selected small states, and seeded larger bounded sequences. Validate
occupancy, reachability, chain, separators and key conservation after each
stable step. Do not use shared generated expected outputs as the only oracle.

Exit criteria:

- Correct cases: empty/single-leaf tree, equality-right search, missing key,
  range gaps/endpoints, duplicate insert, absent delete, simple update,
  both leaf split sizes, internal/root split, three-level split, both donor
  directions, leaf/internal merge, both internal donor directions, root
  collapse, last-entry deletion and ancestor separator changes without underflow.
- Invalid cases: malformed/duplicate-key JSON, bool/int coercion, bad IDs,
  cycles/DAGs/orphans, bad leaf chain, unequal depths, key duplication/loss,
  invalid bounds, cross-parent repair, impossible separator and repair budget.
- Python/JavaScript agree on independent expected facts and semantic identity;
  local HTTP does not require secure-context hashing.
- Both actual host validators accept real engine outputs and reject corrupted
  variants. Exercise/result/binding identities and incomplete-result rules hold.
- Cancellation, work refusal, timeout and next-evaluation recovery work under
  unchanged CSP in Chromium, Firefox and WebKit.
- An engine-only wheel/sdist has complete SDK inventory and payload parity.
  Installed tests import the wheel, not the source checkout.

## B2 — prepare lessons, diagrams and static editions

Implemented locally in version 0.2.0. The six-example 16:9 deck and taller 4:3
stress deck build in English and German. A preparation hook checks each worked
certificate; TikZ shows a connected tree or a page map with explicit pointers.
The style refuses excessive vertical compression. Live, handout and static
PowerPoint omit solutions; solution PDFs explain the checked result. All three
direct-pdfLaTeX editions reuse the preparation identity. See the B2 record for
measured evidence and exact remaining gates.

Add the revision-2 authoring hook, envelope, checked worked certificate,
private/public split and thin LaTeX wrapper. Build one lookup/range/insert/delete
lesson progression plus the cascade and root-shrink demonstrations.
Generate diagrams and explanatory steps from the checked semantic model.

Exit criteria:

- Live deck, handout, solutions, static PowerPoint and local direct-pdfLaTeX
  use the same preparation identity and mathematical result.
- Incorrect worked certificates stop preparation. Changed source/style/assets
  fail freshness checks. Source confinement and explicit enablement remain intact.
- Exercise artifacts contain no unrevealed solution, private trace or author
  source accidentally copied from the preparation directory.
- Render and inspect PDFs, exported slides and long/small trees. Trees, labels,
  answer space and multi-step explanations are readable. The split between
  record entries, separator copies and child pointers is visually consistent.
- The style command, profile/lock setup and TeX dependencies are documented
  against the actual installed package, not inferred from the proposed names.

## B3 — lesson state and authoritative feedback (implemented)

Implemented phases, configured feedback release, per-actor versions, presenter
guards, receipts, selection/sharing and replay cursor. Save only one certificate
and compact feedback per actor. Use SDK evaluation/cancellation effects and
complete persisted binding identities.

Exit criteria:

- Independent students can submit concurrently. Duplicate request receipts,
  lost acknowledgements, same-actor devices and two presenters are deterministic.
- Existing-actor replacement works at the actor ceiling and a full job queue.
  Superseded answers, old epochs and mismatched results cannot overwrite feedback.
- Closing retains accepted pending jobs; revealed→open requires reset.
  Unavailable/failed evaluation is operational feedback, not an incorrect answer.
- Counts, select/share/version changes and replay cursor cannot leak private
  inspection records. Test actual public/participant/projector payloads.
- Admission reserves the private actor-digest key, answer and eventual feedback bytes.
  Measure full canonical state, transitions with effects and every view.
  No silent truncation, unbounded history or class-wide copies of tree snapshots.
- Active/reset/navigation state is correct independently of renderer remounts.

## B4 — visual editor and classroom views (software implemented; device gate open)

Build structured controls for descent, interval results, repair choice and
separator/height predictions. Use the same mathematical semantics for local
preview, while keeping authoritative feedback and saved version distinct.
Let students undo/redo their local attempt without sending commands per click.

The focused phone page/sibling panel and keyboard outline are first-class
views; an overview SVG and optional drag gestures supplement them.
The presenter can inspect one attempt, share it anonymously and step through
it or a revealed worked answer.

Exit criteria:

- Actual installed-wheel lesson flows pass in Chromium, Firefox and WebKit
  with the production CSP; retain active network/worker/dynamic-code probes.
- Verify all four tasks with keyboard and touch at 320-pixel width, zoom/reflow,
  reduced motion and English/German. Inspect screenshots and screen-reader output.
- Dirty drafts, focus, selection and undo survive unrelated view updates;
  same-actor conflicts and reset are explicit; late imports/previews cannot
  revive a disposed mount. Wait for actionable controls before touch tests.
- Slow preview work yields to the UI and obsolete work is cancelled/ignored.
  Do not spawn workers from the restricted evaluation worker or widen CSP.
- A physical phone over ordinary LAN HTTP can complete the operations.
  Desktop emulation is recorded separately.
- Presenter/projector views retain the exercise, legend and readable replay;
  closed, pending, revealed, failure and missing-plugin/static fallback states
  remain understandable.

## B5 — measure and prepare a release

Measure the provisional 48-participant workload with answer replacement,
two presenters, projector, reconnects and one slow/failed evaluator.
Record named hardware/OS/browser, p95/worst UI and feedback latency, queue age,
worker memory, state/effect/view bytes and fairness. Provisional pilot targets
are local interaction p95 below 200 ms, UI work chunks below 16 ms, and burst
feedback p95 below 10 s / worst below 30 s. Confirm or revise after measurement;
these are not promises from finite checks.

Run isolated scenarios for host alone, original coordinate/distance pair,
B+ engine/lesson alone, transaction plus relational plus B+, and all providers.
Check ID/style/resource collisions, metadata-only disabled discovery, pinned
resource changes and no-plugin regressions if host code changed.

Transfer the identical wheel bytes between Windows and Linux. Keep CI domain,
packaging, browser matrix and artifact-consumer jobs independent; install the
actual TeX dependencies so prepared-authoring checks run rather than skip.
Record exact host/provider revisions, wheel/payload/schema hashes and hosted
results. An unpublished local host commit is still a release blocker.

Inspect public archives and a real projector recording to confirm privacy and
readability. Publish and add an immutable catalog entry only under a subsequent
release instruction, after the compatible host pin and all required gates pass.
No course pin or course environment changes are implicit.
